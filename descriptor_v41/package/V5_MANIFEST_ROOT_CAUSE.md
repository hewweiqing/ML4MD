# v5 manifest mismatch root cause

The released v5 archive digest `d755f28de2d8cfb37f729198626a740d98d3d869463a3fef8d238bbd9b287d6f` is intact, but its internal aggregate algorithm was operating-system dependent.

The v5 generator called `sorted()` on native `Path` objects before converting them to canonical POSIX relative strings. On Windows, path ordering placed lowercase `alignn_stage2/...` near uppercase root files; on Linux, lexical POSIX ordering is case-sensitive. In the released v5 manifest, the first observed ordering divergence from Linux lexical order was index 33: Windows stored `STAGE2_ENV_SPEC.json`, while Linux expected `STAGE_0B_AUDIT.json`. The same file hashes were concatenated in a different order, producing the confirmed DelftBlue `aggregate_sha256 mismatch`.

Generated `.pyc` files and `__pycache__` directories were also present in v5 because importing the manifest helper during archive construction regenerated bytecode after an earlier cleanup. The v5 hash function excluded those paths, so they did not contribute to the aggregate mismatch. Their presence nevertheless violated archive hygiene and is independently corrected in v6.

Version 6 sorts canonical POSIX relative strings lexically, hashes every immutable file except the manifest, forms exact lines `<sha256>  <relative-path>\n`, hashes their exact UTF-8 concatenation, and independently reconstructs those bytes during verification.
